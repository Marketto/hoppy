# Themes and mascots

The app is minimal: one mascot, one switch, a list, one button. Themes change mood,
motion and decoration, never the layout or the features. Approved comps: the design
canvas "Hoppy · proposte stile pubblicità giapponese" (four animated proposals). Mascot
preview: `assets/brand/mascots-preview.png`.

## Choosing a theme

- First launch opens `ThemePickerActivity` (Android has no install-time UI): five live,
  animated cards; the user picks one. It can be changed later from the ⋮ menu.
- The pre-selected card comes from the OS (`ThemeSuggestion`): **high contrast → Manga**,
  else **dark mode → Night**, else **Purikura**. The card shows why it was suggested.
- People upgrading from the two-theme build keep their choice (Kawaii → Purikura,
  Pro → Night) and skip the picker.

## Desktop send window

`hoppyw send` on Windows, macOS and Linux shows one themed window (ADR 0011,
`crates/hoppy-cli/src/sendui/web/`) mirroring Android's send screen: mascot on top (idle
bob/hop per theme, looking around when nobody is found, the happy mascot jumping on
delivery), the file line, device cards with an initial avatar and ✓/🔒/⚠ badges, a
progress bar, the inline 4-emoji verification panel, and one Japanese decor sticker per
screen (だれかいる？ searching / nobody, 近くにいるよ devices, 送信中 sending, とどいた！
delivered).

- **Choosing**: tray menu *Theme* ▸ / *Tema* ▸ (device.json `theme`). Never chosen: the same
  rule as `ThemeSuggestion` (high contrast → Manga, else dark → Night, else Purikura), from
  the OS (`crate::theme`, `platform::system_look`), re-read for each window.
- **Palettes**: the table above, as CSS variables in `app.css` (one block per theme); text
  sits on solid surfaces (`--surface`, `--card`), pastels only decorate. `tools/contrast.py`
  checks every desktop pair too (text 4.5:1, focus ring and progress bar 3:1).
- **Fonts**: the same OFL fonts, re-subset to Latin + kana + the decor characters as WOFF2
  (`python3 tools/fonts.py --desktop` → `sendui/web/fonts/`, ~320 KB; re-run after changing
  the decor text). Yusei Magic is Android-only.
- **Motion** (CSS only): Purikura checkerboard + dots scrolling diagonally, dotted sticker
  ring pulsing, jelly button shine; Showa slowly rotating sunburst, mustard disc, hard offset
  shadows, light band sweeping the main button; Manga rotating speed lines + screentone,
  big hops, buttons pressing into their shadow; Yume shifting sky, drifting clouds, rising
  bubbles, twinkling stars, glossy bubble behind the mascot; Night calm starfield, breathing
  teal halo, glint across the sunglasses. All of it stops under `prefers-reduced-motion`
  (the OS "reduce motion / animation effects" setting) and while the window is hidden;
  Windows high-contrast mode (`forced-colors`) drops the decoration.

## Mascots

Generated by `tools/gen_mascots.py` — never edit the outputs.

- `mascot_kawaii` — mochi bunny (Purikura, Showa, Manga, Yume); `mascot_happy` — closed
  "^ ^" eyes and open mouth, used to celebrate a delivery; `mascot_pro` — cool bunny with
  sunglasses (Night).
- Named groups animate natively via `mascot_<name>_anim.xml` (AnimatedVectorDrawable):
  ears wiggle, eyes blink, cheeks blush, sunglasses glint. Body motion (hop, bob, sway,
  nod, celebrate) is done in `MascotView`.

## App icon

Must be recognisable at 48 px in a busy share sheet (a pale cream icon with a small bunny
read as "dull" on a real phone). Generated by `tools/gen_mascots.py` like the mascots:

- **Background** `ic_launcher_background` — saturated diagonal gradient Purikura pink
  `#F27A9B` → lavender `#B994E8`, a soft top-left gloss and a few white sparkles.
- **Foreground** `ic_launcher_foreground` — the Kawaii mascot as a sticker: scaled ×0.37
  so its body is ~52dp wide (~72% of the 72dp visible area), ear tips near the top of
  that area, body inside the 66dp safe zone; white die-cut border plus a soft violet drop
  shadow so the cream bunny pops on pink; ink strokes ×1.4 for small sizes. Geometry
  constants (`ICON_*`) are checked so nothing is clipped by a circle mask.
- **Monochrome** `ic_launcher_monochrome` (themed icons) — the same silhouette at the
  same size, eyes punched out.
- Sharing shortcuts (`ui/ShareShortcuts.kt`) draw these two layers, so the share sheet
  shows the same icon. minSdk 29: adaptive icon only, no legacy PNGs.
- Desktop/web: `assets/brand/hoppy-icon.svg` (both layers, unmasked) →
  `python3 tools/gen_icons.py` (Playwright + Pillow) → `assets/brand/hoppy-512.png`
  (portal, social preview) and `assets/brand/hoppy.ico` (Windows exe/installer), a rounded
  square of the central 80 units.
- iPhone/iPad: `python3 tools/gen_icons.py --ios` → one opaque 1024 px square of the same
  80 units (iOS rounds the corners) in `apps/ios/Hoppy/Assets.xcassets/AppIcon.appiconset`,
  and the Kawaii/Happy mascots as PNG @2x/@3x in `apps/ios/Shared/Mascots.xcassets`. The iOS
  app has only Purikura (light) and Night (dark mode) for now: `apps/ios/Shared/Theme.swift`,
  same colors as Android, pairs checked by `tools/contrast.py`.

## Music

Each theme has an original 16-bit-console-style chiptune (pulse waves, triangle bass,
2-op FM leads/bells/e-piano, noise drums, echo), generated by `tools/gen_music.py` — never
edit the outputs; run `python3 tools/dev.py music`. Lengths and tempi for code:
`assets/music/manifest.json`.

| Theme | Key | Idle → transfer BPM | Mood / transfer twist | Done jingle |
| --- | --- | --- | --- | --- |
| **Purikura** | D major | 108 → 135 | gentle pulse-wave hook, sparse offbeat chords, kick + brush; transfer adds four-on-the-floor kick, 8th hats, octave-arpeggio bass, 16th arpeggio, harmony on the repeat | rising D-major arpeggio to a high A, crash |
| **Showa** | G major, yonanuki pentatonic (G A B D E) | 98 → 122 | relaxed kayōkyoku shuffle with vibrato lead, FM "koto" stabs, brush and a lone woodblock; transfer straightens into a light 60s "eleki" drive with tom fills | pentatonic climb, woodblock roll |
| **Manga** | C major + comic chromatic notes | 112 → 140 | comic hook played softer and more legato, sparkle doubling an octave up, brush backbeat; transfer: punchier lead, octave bass, claps, snare fills | "ta-da" with a slide-up |
| **Yume** | F lydian (maj7, G/F) | 80 → 100 | soft FM flute + bell, 8th arpeggios drenched in echo, triangle pad, almost no drums; transfer: light breakbeat with brush and shaker, 16th arpeggio, arpeggiated bass | sparkling Fmaj9 arpeggio |
| **Night** | D minor (m9 chords, bII maj7) | 78 → 98 | slow lo-fi with brush and swung shaker, FM e-piano, FM bass; transfer becomes a soft city-pop disco groove (open hats, octave bass) | Dm9 → Dmaj9 resolution |

Idle loops are deliberately calm: soft-attack legato leads, lighter kick, brushed snare,
no busy hats, a little more echo and low-pass (6.5–6.8 kHz). Transfer loops are about
1.25× the idle tempo, still clearly faster and busier, but not driving.

- **idle** (8 bars) and **transfer** (16 bars: hook, then hook with a harmony line) are
  seamless loops of an exact number of bars; **done** (≈2 s) is a one-shot.
- Desktop (Windows) uses only the Purikura music, as 8-bit WAV in `assets/music/`
  (`PlaySoundW`): **`hoppyw send` plays only the done jingle** on delivery (no loops while
  sending); the **installer** plays `desktop_idle.wav` (extra quiet, −26 dB RMS) in the
  wizard and `desktop_done.wav` on the finished page, with a "♪ Music" checkbox, never in
  `/SILENT` or `/VERYSILENT` installs. The tray receiver and the CLI are always silent.
  Only `desktop_done.wav` (16 kHz) is embedded in `hoppyw.exe`; `desktop_idle.wav` is
  12 kHz to stay under ~250 KB. There is no desktop transfer loop.
- **When it plays**: only while the app (or desktop installer) is visible, never when
  muted, and during a transfer only on the **sender**. Idle plays while the app is open
  and choosing a device; switch to transfer when the send starts (crossfade ~300 ms on
  the next bar boundary, `bar_ms` in the manifest); play done once on success (stop the
  loop first); on decline, error or cancel crossfade back to idle, no jingle. While a
  device is **receiving** it is silent even if its app is open (it may be in a pocket or
  a meeting); it gets a system notification at the end instead. Stop in `onStop`.
- **Android** (`app/src/main/java/app/hoppy/audio/`): `Music` counts started activities
  (250 ms grace for screen switches/rotation) and fades out (200 ms) when none is visible.
  `MediaPlayer` loops, `USAGE_GAME`/`CONTENT_TYPE_MUSIC`, volume 0.4 (done jingle 0.55). It never starts if
  another app is playing (`isMusicActive`), takes `AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK` with
  `setWillPauseWhenDucked(true)` and pauses on any focus loss (permanent loss: silent until
  the next visit). Silent while `ReceiveService.receiving` (offer accepted → connection
  closed), even with the app open. The theme picker previews the card on screen. The done
  jingle may finish after the send screen closes. Mute: overflow menu *Music*
  (`Prefs.music`, default on); reduced motion does not mute. Bar lengths are a table in
  `MusicTiming` (pure, tested against `assets/music/manifest.json` by `MusicTimingTest`):
  update it when `tools/gen_music.py` changes tempo or bars. Players are released after
  30 s of silence or on `onTrimMemory`.
- Loudness is matched across themes and mastered quiet at the source: loops RMS ≈ −24 dBFS,
  done jingles −21 dBFS, installer idle and portal −26 dBFS, peaks ≤ −3 dBFS. Switching
  theme never jumps in volume.
- Original compositions only: no quotes or imitations of game, anime or pop tunes.

**Download portal** (`site/`): its own track `portal` — Eb major, 84 BPM, 16 bars (45.7 s),
a relaxing, cozy, gently swaying "home" tune (soft legato pulse lead with vibrato, round FM
bass, brushed drums, maj7/add9 chords, flute + bell join on the second half). Quieter than
the app (RMS ≈ −26 dBFS, page gain 0.45 with a 1.5 s fade-in) and warm (4.8 kHz low-pass). Generated to `site/music/portal.ogg`
(Vorbis, preferred) and `portal.mp3` (fallback), 32 kHz mono, plus `portal.json` (exact
loop length) for the player. The page's floating ♪ button is **off by default** (no
autoplay, WCAG 1.4.2); a remembered "on" starts only at the visitor's first interaction;
it pauses when the tab is hidden. See `.claude/skills/hoppy-release/SKILL.md`.

## Code map (Android)

`apps/android/app/src/main/java/app/hoppy/ui/theme/`: `HoppyTheme` (enum + style +
mascot + migration), `ThemeSuggestion` (pure rules + `SystemThemeSignals` reader),
`ThemeBackgroundView`, `MascotStageView`, `MascotView`, `HoppyButton`, `ShineDrawable`,
`ButtonFx`, `HomeDecor`, `Motion` (ticker, `HostAware`, fonts). Styles in
`res/values/themes.xml`; the `hoppyThemeKind` attr enum order must match `HoppyTheme`.

## Rules

- Original characters only; they must not resemble existing mascots or brands.
- Colors come from theme attributes or `HoppyTheme`; never hard-coded in layouts.
- Motion: every animation stops in `onStop`, on detach and when hidden, and is off when
  the system "remove animations" setting is on. Custom animated views implement `HostAware`.
- Any new Japanese text needs `python3 tools/fonts.py` (fonts are subsetted).
- **Accessibility (WCAG 2.2 AA)**: text ≥ 4.5:1, large text and state-bearing UI ≥ 3:1, in
  every theme. Pastel colors are for decoration only; anything carrying text uses the deeper
  shades above. `python3 tools/contrast.py` (part of `dev.py check`) checks every theme
  text/background pair — add new pairs there. Manga must stay the highest-contrast theme.
